# 异步图片预载系统 (Async Image Preloader) 架构计划

_状态：草案 / 待执行_

## 1. 业务痛点
目前 `x-assistant` 的脚本（如 `read_post.py`）在解析出推文包含图片时，仅返回 `[Image: https://pbs.twimg.com/media/...]`。
这导致 AI Agent 若需要查看图片，必须手动调用网络工具去下载。如果同步在 Python 中全部下载，会严重拖慢 JSON 的返回响应速度；如果不下载，Agent 操作成本又过高。

## 2. 目标设计：“异步 Promise” 模式与双锚点替换
**核心理念：基于计算决定论，在文件系统层面实现异步 Promise。**

由于 X.com 的图片 URL 可以通过提取其固定格式（如 ID 和后缀）推导出确定性的本地文件名，我们可以利用这一点实现极速的异步闭环。

### 核心机制
1. **确定性命名与占位**：
   在 `read_post.py` 等脚本解析文本时，用正则匹配所有的 `[Image: URL]`。
   对 URL 进行 MD5 哈希并提取后缀（如 `.jpg`），生成确定的本地缓存路径：`/tmp/browser-bridge-cache/<MD5>.<ext>`。
2. **双重锚点替换**：
   将原文瞬间替换为：`[Image Local: /tmp/.../<MD5>.jpg | Remote: URL]`。同时提供本地路径（供 Agent 未来查阅）和远程路径（兜底防丢）。
3. **完全分离的后台下载**：
   主脚本将这些图片 URL 连同其对应的本地路径发送给一个**完全独立运行的后台脚本**（例如 `scripts/async_image_downloader.py`）。主脚本通过 `subprocess.Popen` 以非阻塞 (detached) 模式拉起它，然后瞬间退出并返回 JSON 给 Agent。
4. **时间差互补**：
   Agent 在阅读 JSON 并生成回复的这几秒钟“思考时间”内，后台脚本会默默将图片下载到对应的本地路径。等 Agent 决定读取本地路径时，图片已经就绪。

## 3. 预期成果
- **速度零损耗**：主脚本接口响应时间不会因为大量图片的下载而延长哪怕 1 毫秒。
- **Agent 零门槛**：Agent 拿到的直接是准备好的绝对路径，想看图直接 `read_file`。
- **安全防丢**：如果下载失败，Remote 链接仍保留在上下文中，逻辑完美闭环。
- **自动垃圾回收**：后台下载脚本自带清理逻辑，防止缓存撑爆硬盘。
